# groundtruth v0.0.4

A hardening release driven by a real deployment: groundtruth running on k3s with a
local Ollama model, ingesting the maintainer's own project docs. Every change here
fixes something that broke in that loop — the image, the security context, the web
forms, the agent's chat framing, and the ingest step that fails most often on a
local model.

No spec changes. `docs/requirements.md` is unchanged.

## Ingest — organize retries on a validator rejection

The organize step turns distilled items into `create_note` / `update_note` calls,
and the validator (§7.6) rejects the batch if any `[[wikilink]]` dangles, a
`create` collides with an existing note, a folder is undeclared, and so on. On a
local model those rejections are common — a dangling wikilink alone accounted for
most ingest failures in testing — and each one failed the whole job.

The organize stage now re-runs on a `ValidationRejectionError`, feeding the exact
rejection (rule, note, detail, and a rule-specific hint) back to the model for
another attempt. `limits.organize_max_attempts` (default `2`, `1` disables) bounds
it.

This is **not** sanitize-and-continue (ADR-5): nothing is silently repaired. The
model redoes its own output, every attempt goes through the same validator
unchanged, and once the attempts are spent an still-invalid batch fails the job
loudly with the last rejection — exactly as before, just after N tries instead of
one.

## Deployment fixes

| # | Fix |
|---|---|
| #86 | Release image build failed — `hatchling` validates `readme = "README.md"` but the Dockerfile never `COPY`ed it. Added the copy, **and a `docker` CI job that actually builds the image on every PR** so a broken Dockerfile can't reach a release again. |
| #87 | `service.nodePort` to pin a NodePort; `config.llm_timeout_s` (default 60) — a large local model prefilling a big context blows past the old hard-coded HTTP timeout, and a timed-out call retries, so jobs failed after ~3×. Raise it (and `limits.max_wall_clock_s`) for gemma-class local models. |
| #89 | `CreateContainerConfigError` on k3s: the image ended `USER groundtruth` (a name), which containerd can't verify against `runAsNonRoot: true`. Image now runs as numeric `USER 1000:1000`; chart sets `runAsUser` / `runAsGroup: 1000` and `podSecurityContext.fsGroup: 1000` (so the PVCs are writable). |
| #90 | Web UI query and ingest forms returned **422**. The JSON API's `POST /query`, `POST /ingest`, `GET /jobs/{id}` are registered before the web router and FastAPI first-match wins, so form bodies hit the JSON parsers. The htmx form/poll endpoints moved to `/ui/query`, `/ui/ingest`, `/ui/jobs/{id}`. |
| #91 | Ingest and query against Qwen (and some Llama/Mistral builds) failed with HTTP 500 `"no user query found in messages"` — the agent loop opened with a system-only messages array. It now opens with a `user` turn. |
| #93 | Dangling-wikilink rejections: the organize prompt only showed the survey-relevant notes. It now gets the full list of every note path in the vault as valid link targets. |

## Web UI (#92)

- New **Queue** page (`/queue`) — every ingest job with live status, note counts,
  durations, and the failure stage + reason for failed jobs; auto-refreshes.
- `JobRecord` now carries `created_at` / `updated_at`; `GET /jobs` returns the
  recent job list as JSON.
- The whole UI was rebuilt on a small design system — design tokens, dark mode,
  a sticky header with nav, status badges, cards. Still server-rendered
  Jinja2 + htmx, no build step.

## Upgrading

```sh
helm upgrade --install gt oci://ghcr.io/psenna/charts/groundtruth --version 0.0.4 \
  --reuse-values
```

If you are coming from an image older than v0.0.4 and see
`CreateContainerConfigError`, add
`--set securityContext.runAsUser=1000 --set securityContext.runAsGroup=1000`
until the pod is on the v0.0.4 image.

For a slow local model, raise the two timeouts together:

```yaml
config:
  llm_timeout_s: 600
  defaults:
    limits:
      max_wall_clock_s: 900
      organize_max_attempts: 2
```

## Known limitations

- A local dense ~30B model at a large context window is slow enough (~25 s/call)
  that ingest jobs can still trip `max_wall_clock_s`; drop that model's context
  window or use a faster/hosted model for the reduce and organize stages. The tag
  step still over-applies broad tags.
- Single shared bearer token; no multi-user auth (out of scope, §3).
