# groundtruth v0.0.7

More ingest-quality fixes from reviewing a qwen3.6 run of the maintainer's
project docs. No spec changes.

## Grounding: the reduce step no longer keeps inference

One note in the test vault, `projects/ai-sandbox/AI Sandbox Overview.md`, was
pure speculation — *"DependaProxy planned features include AI-assisted
validation. **This suggests the existence of** an AI Sandbox component…
**potentially leveraging** the existing middleware…"* — a note built by
connecting a roadmap phrase in one doc to the *name* of another project.

`reduce.md` now explicitly discards inference: *"anything the text does not
itself state. Do not connect two facts into a third, do not conclude, do not
speculate. Drop any item that leans on 'this suggests', 'this implies',
'likely', 'potentially'…"* — and: *"every kept item must be traceable to a
sentence in the text."*

## Unfenced frontmatter is now stripped from note bodies too

v0.0.6 (#99) strips a `---` … `---` block the model prepends to the body. The
model also writes the same thing **without** the fences:

```
tags:
- ai-sandbox
- validation
sources:
- distilled-design-specification

# AI Sandbox Overview
```

`_strip_body_frontmatter` now also removes a leading run of `tags:` / `sources:`
/ `title:` … lines (and their `- item` values) up to the first blank line — but
only when the block *starts* with a known frontmatter key, so ordinary prose
like `Note: see above` is untouched.

## Folder discipline

`groundtruth/CLAUDE.md` failed because the model created a note in
`projects/groundtruth/ci/` — a sub-folder it invented under the declared
`projects/groundtruth/`.

- `organize.md` now says: use a declared folder exactly as written, never invent
  a sub-folder; and *"stay on the input's subject — do not create a note about a
  different project just because the text mentions it."*
- The validator's retry feedback for a `folder` rejection now lists the declared
  folders verbatim, so the model can see exactly what is allowed.

```sh
helm upgrade --install gt oci://ghcr.io/psenna/charts/groundtruth --version 0.0.7 \
  --reuse-values
```

No values you must change.

## Known limitation — tags are per-ingest, not per-note

The tag step runs once per ingest, on the distilled items, and the same tag list
is stamped on **every** note that ingest creates. When one source doc becomes
several notes across folders, they all get the same tags — and a note the model
mis-filed picks up the source doc's tags rather than its own. Making tagging
per-note is a pipeline change tracked separately.
