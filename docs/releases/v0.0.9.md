# groundtruth v0.0.9

Ingest-quality work from reviewing real local-model runs (qwen3.6 and qwen3.8
ingesting the maintainer's project docs), plus job-observability on the web UI.
No spec changes.

## Ingest

### Per-note tagging (#104)

The tag step ran **once** per ingest, on the distilled items, and the same list
was stamped on every note that ingest produced. A source doc spanning three
projects tagged all its notes with all three; a note the model filed under the
wrong folder still picked up the source doc's tags; and the "2–6 tags" bound
from v0.0.6 could not hold for a multi-topic ingest.

`_tag` now takes a note **body** and runs **once per note**, after organize and
before validation — a note is tagged for what it says. The retry and the
count/prose guidance still apply, per note.

### Organize: no overview-plus-stubs, no pointer-only notes (#105)

One ingest produced a 150-line overview note *and* seven 3–10 line stubs
covering the same material, several of them just "full instructions are in
`docs/x.md`". `organize.md` now says: don't both write an overview and split its
sections into their own notes — pick one shape; and every note must carry
substance, not just be a pointer.

### The organize loop is now bounded by `max_tool_calls` (#107)

The survey loop was metered by the agent budget; the organize loop was not —
`WriteTools` ignored the budget, so the only bound was the loop's hard cap of
`2 × max_tool_calls + 10`. A dense, thorough model (qwen3.8) ran ~70
`create_note` / `update_note` calls without converging and the job failed with
an opaque "agent loop did not converge".

`WriteTools` now charges the budget on every call, like the read-only tools. A
runaway organize now fails cleanly with `organize budget exhausted` and the same
remedy — raise `limits.max_tool_calls` for the vault.

## Web UI — job observability

### Wait time vs run time (#106)

The queue page's single "Duration" counted a job's time **in the queue** as run
time. `JobRecord` now has `started_at` (stamped once, on the QUEUED → RUNNING
transition), and the queue table shows two columns:

- **Waited** — created → started
- **Ran** — started → finished

### Text size + a per-job detail overlay (#108)

- `JobRecord.source_bytes` — the UTF-8 size of the ingested text; a **Text**
  column on the queue.
- Each job id is a button that opens a detail overlay with the full record:
  text size, waited/ran, all three timestamps, source + commit sha, per-stage
  timings, per-role token usage, the created/updated note **paths**, and the
  errors from earlier attempts.
- `GET /jobs` returns all of it too (`source_bytes`, `started_at`,
  `stage_timings`, `token_usage`, `attempt_errors`), errors redacted.

## Notes from the model comparison

- **qwen3.8:27b dense at `temperature: 0.2`** gave the best note quality of any
  config tried: proper overview + focused-notes granularity, cross-ingest
  consolidation (a later doc *updates* the notes an earlier one created),
  consistent wikilinks. It is slower than the MoE and needs a higher
  `max_tool_calls`.
- Set `reasoning_effort: none` and `params: {temperature: 0.2, presence_penalty: 0}`
  on `models.default` for any local model — the defaults (`temperature 1`,
  `presence_penalty 1.5` for Qwen3) are tuned for creative writing and hurt the
  extraction stages.

## Upgrading

```sh
helm upgrade --install gt oci://ghcr.io/psenna/charts/groundtruth --version 0.0.9 \
  --reuse-values
```

No values you must change. Consider bumping `limits.max_tool_calls` (40–60) if a
dense model trips `organize budget exhausted` on your larger source docs.
