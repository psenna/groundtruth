# groundtruth v0.0.6

Ingest robustness against a chatty local model, from inspecting a real qwen3.6
ingest of the maintainer's own project docs. No spec changes.

## Tool-argument normalisation (#99)

A local model, told "supply the folder, the title, and the body", tends to:

- **pass a filename as the title** — `create_note(folder, "core_engine.md", …)` →
  `sanitize_title("core_engine.md") + ".md"` = `core_engine.md.md`. It also
  created `core_engine.md` *and* `core_engine.md.md` with identical bodies in the
  same batch, and the duplicate-path check didn't fire because the paths differ.
- **prepend its own frontmatter to the body** — `---\ntags:\n  - x\n---\n…` — so
  the committed note ends up with two frontmatter blocks (the model's stale one
  plus the real one the system builds).

Both showed up on roughly half the notes in the test run.

`WriteTools` now normalises the arguments before buffering:

- a trailing `.md` / `.markdown` / `.txt` is stripped from the **title**, so
  `create_note("x", "Foo")` and `create_note("x", "Foo.md")` resolve to the same
  path and the existing duplicate check catches the double-create;
- a single leading `---` … `---` block is stripped from the **body**, but only
  when the fenced content actually contains a frontmatter key — a stray `---`
  horizontal rule is left alone.

This is not ADR-5 sanitise-and-continue: it normalises the *packaging* of the
call, not the model's content or its create-vs-update decision.

## Retry the tag step and empty organize (#100)

#94 re-prompts the **organize** step when the write validator rejects it. Two
more failure classes are now handled the same way:

- **`tag` step returns prose** instead of a tag list (`kubernetes (implied by
  context… let's stick to explicit tech. Wait, t…)`). `_tag` now re-prompts once
  with the parse error fed back before failing the job.
- **organize finishes without calling a write tool** ("organize produced no
  writes"). It is now retried within `limits.organize_max_attempts` with a "you
  must write at least one note" nudge.

Both still fail the job loudly once the attempts are spent — nothing is
fabricated or skipped.

## Tag over-application (#100)

Every note in the test run carried the same ~10 tags, including two-line stubs.
`tag.md` now bounds it: *"a tag names a primary subject of the note — not every
technology the text mentions… most notes need 2 to 6"*, and forbids prose,
numbering, and parenthetical explanations explicitly.
