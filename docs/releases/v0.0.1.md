# groundtruth v0.0.1

First tagged release. The system described in [`docs/requirements.md`](../requirements.md)
is implemented end to end — ingestion, recovery, grounding verification, and all three
interface surfaces — behind a single deployable container.

## Highlights

- **Ingestion pipeline (§7).** Raw text → tagged, distilled, cross-linked Markdown notes.
  One ingest is exactly one commit, all-or-nothing; any failure at any stage rolls back
  and commits nothing, so `git revert` is a complete retraction. Never ingests into a
  dirty working tree.
- **Recovery pipeline (§8) with unbypassable grounding verification (§9).** A question
  returns a Markdown answer whose every claim carries a `[[citation]]` to a note that
  actually exists — or an explicit refusal. A grounding-check failure is downgraded to a
  refusal, never a hedged answer. Budget exhaustion refuses rather than answering
  partially.
- **Shared retrieval agent (ADR-3).** "Find the notes relevant to this text" is the same
  `ls`/`grep`/`read` agent loop during ingestion and during recovery — no embeddings, no
  separate index to drift from the notes.
- **Vault = a plain Obsidian repo.** Markdown + YAML frontmatter + `[[wikilinks]]`,
  git-versioned. `schema.md` is user-authored and the pipeline never writes it; the active
  tag vocabulary is derived from note frontmatter, cached against the vault's `HEAD` sha,
  never stored (ADR-12).
- **Three interface surfaces from one ASGI app (§4.2, §10):** REST API, MCP server at
  `/mcp` (8 tools, so external agents can query and contribute), and a read-only web UI
  (`/`, `/ingest`, `/browse`). `/health` is unauthenticated; `bearer` auth is opt-in.
- **Per-vault FIFO job queue** with a retry policy and startup reconciliation of
  interrupted jobs; configurable per-role models (`tag` / `reduce` / `answer`) against any
  OpenAI-compatible endpoint.
- **Secrets are environment variables only (§11.4)** — never in config files, commit
  messages, job records, logs, or the vault. `config.yaml` references an env var by name.
- **Observability:** per-stage timings and token counts; optional LLM-call logging
  (off by default — prompts contain ingested content).
- **Golden evaluation:** a fixture vault plus must-answer / must-refuse cases, runnable
  offline (deterministic) or against a real model (`-m eval_live`).

## Deployment

- **Container** — one image serving API + MCP + web. Multi-stage build, non-root system
  user, dedicated `groundtruth` git identity baked in, `/health` HEALTHCHECK, no secret in
  any layer. `docker-compose.yml` wires named volumes for the state dir and the vault
  repos plus a read-only `config.yaml` mount.
- **Helm chart** ([`charts/groundtruth`](../../charts/groundtruth)) — one replica,
  `Recreate` strategy (groundtruth is single-writer: per-vault git repos + a FIFO queue on
  one `ReadWriteOnce` volume), non-root pod/container security context with all
  capabilities dropped, separate `state` and `vaults` PVCs kept on `helm uninstall` by
  default, `config.yaml` from a ConfigMap, secrets by reference from a Secret,
  `/health` liveness + readiness probes, optional ingress, a `helm test` connection pod.
- **Config** — [`config.yaml.example`](../../config.yaml.example) is the full reference.

## Release pipeline

Pushing the `v0.0.1` tag (or a GitHub Release for it) runs
[`.github/workflows/release.yml`](../../.github/workflows/release.yml), which publishes to
GitHub Container Registry:

| Artifact | Location |
|---|---|
| Container image | `ghcr.io/psenna/groundtruth:0.0.1` (also `:0.0` and `:latest`), multi-platform, with SBOM + provenance attestations |
| Helm chart (OCI) | `ghcr.io/psenna/charts/groundtruth:0.0.1` |
| Helm chart (`.tgz`) | attached to the GitHub Release |

The chart's `version` / `appVersion` are stamped from the tag at package time, so the
value committed in `Chart.yaml` only needs to be a sane default.

Install:

```sh
helm install gt oci://ghcr.io/psenna/charts/groundtruth --version 0.0.1 \
  --set-string secret.data.GT_API_KEY=... \
  --set config.defaults.models.default.base_url=http://your-llm/v1
```

## Known limitations

- Single shared bearer token; no multi-user auth (out of scope, §3).
- The reduce step (§7.5) is a prompt-iteration problem — vault quality will keep improving
  past this release; that is expected, not a regression.
- CI installs from PyPI directly. Offline / air-gapped installs go through DependaProxy via
  `scripts/fetch-deps.py` (see `CLAUDE.md`).
