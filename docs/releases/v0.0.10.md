# groundtruth v0.0.10

Ingest-reliability work driven by a four-way local-model comparison (a fixed
10-doc batch against qwen3.6, qwen3.8, and two gemma4 shapes). Dangling
wikilinks and create/update collisions were the two dominant failure modes
across every model; this release attacks both, tightens the organize prompt,
adds full token accounting, and ships a local-model tuning guide.

**One spec change** ([#118](https://github.com/psenna/groundtruth/pull/126)):
§7.6 gains a single, bounded exception to fail-loudly write validation. See
below and the amended ADR-5.

## Ingest reliability

### Create-onto-existing-path is coerced into an update (#111)

`organize` frequently calls `create_note(folder, title, …)` for a path that
already exists — the model decided the body and the exact path, it just reached
for the wrong tool. That hit the validator's `collision` rule and failed the
whole job. `create_note` now buffers such a call as an `update_note` to that
path (§7.5, the newer value wins); nothing about the body is altered. The
`collision` rule stays as the defensive gate, and the coercion is logged.

### Organize retries share one budget (#112)

`_organize_and_validate` built a fresh `Budget` for every validator-rejection
retry, so a stuck model got a brand-new `max_tool_calls` / `max_wall_clock_s`
allowance on each attempt. The budget is now constructed once and metered across
all attempts — the organize *step* is bounded, not each try.

### Terminal dangling-link downgrade (#118) — spec change

A dangling `[[wikilink]]` was the single most common ingest failure, and it
characteristically failed *after* the retry ran. New §7.6 exception: on the
**final** organize attempt, if `link_integrity` is the *only* validator failure,
the `[[ ]]` markup is stripped from each unresolved link in the offending note
(keeping the alias text, else the raw target) and the whole batch is
re-validated. The job commits only if that re-run is clean; a link failure on
another note, or any other rule, still fails loudly with a rollback.

This is **not** a reopening of sanitize-and-continue (ADR-5): it fires only
after every retry is spent, only ever deletes markup around text the model
itself wrote, is scoped to one check, and is recorded on the job
(`JobRecord.link_downgrades`) and the stage log — never silent. Every other
validator failure still aborts the job with nothing staged.

### Organize prompt: overlap and titles (#113, #114, #115)

- **No overlapping notes (#113)** — the model produced six thin notes for one
  subject (a note per aspect of a component). `organize.md` now says to check
  for an existing note before creating, and that "a different aspect of the same
  subject is not a different note".
- **No folder-prefixed titles (#114)** — a note in `projects/git-proxy/` was
  titled `git-proxy Configuration`, so the folder name showed up twice in the
  path. The prompt now asks for `Configuration` / `Deployment` / `Internals`.
- **Tags anchored to the note's own path (#115)** — the per-note tag call
  (v0.0.9) is now given the note's vault path, so an update from a
  differently-themed later ingest can't pull a note's tags off its home topic.

## Token accounting (#116, C7)

Only the single-call stages (`reduce`, `tag`) reported token usage. The
agent-loop stages (`survey`, `organize`) and the entire query path reported
nothing.

- `run_agent` now sums usage across every model call and returns it on
  `AgentOutcome.usage`.
- `JobRecord.token_usage` is keyed by pipeline stage
  (`survey` / `reduce` / `organize` / `tag`) and holds a `TokenCounts`
  (`prompt` / `completion` / `total`), not a bare int. Legacy job records still
  load.
- The query path carries `token_usage` too: `AnswerResult` and `Refusal` both
  have it, it survives the grounding check, and `to_payload` surfaces it on
  REST **and** MCP. `recover` emits a `query` cost log line.
- The web job-detail overlay shows prompt / completion / total per stage plus a
  total row.

## Docs

### Local-model deployment and tuning guide (#117)

New [`docs/local-model-tuning.md`](../local-model-tuning.md), linked from the
README:

- which model runs which stage, and the resolution rules — notably that
  `model:` is **not** inherited from `models.default` (`tag` / `reduce` /
  `answer` keep their built-in `qwen2.5:*` unless set; only `organize` uses
  `default`), with a full worked config;
- `reasoning_effort: none` + low-temperature / zero-`presence_penalty` as the
  local-model baseline, and why;
- context-window vs. prefill-speed (32k is usually enough);
- `max_tool_calls` for dense (40–60) vs. MoE models;
- a "what to expect" table by backend shape.

The stale "inherited by the roles below" comments in `config.yaml.example` and
`values.yaml` were corrected to spell out the `model:` exception.

## Upgrading

```sh
helm upgrade --install gt oci://ghcr.io/psenna/charts/groundtruth --version 0.0.10 \
  --reuse-values
```

No values you must change. If a dense local model still trips `organize budget
exhausted` on large source docs, raise `limits.max_tool_calls` to 40–60 — see
the new tuning guide.
